# SYNKRA: где находятся данные и как ими управлять

Основная папка проекта на вашем компьютере:

```text
C:\Users\USER\Documents\Codex\2026-10-13\http-localhost-3000-http-localhost-3000\outputs\synkra
```

Сайт хранит информацию в серверной базе SQLite, которая в этом проекте обслуживается Cloudflare D1. Это одна база с таблицами, а не отдельный файл на каждого клиента или абонемент. Закрытие браузера, обновление фотографий и перезапуск сайта записи не удаляют.

## Реальный файл базы на этом компьютере

```text
.wrangler\state\v3\d1\miniflare-D1DatabaseObject\faaf2b0445ab934c3aac48ddf0cdfade8f9bac050be98993748742cdd2cb05fb.sqlite
```

Путь указан относительно папки проекта выше. Рядом могут находиться файлы `-wal` и `-shm`: это служебные файлы работающей базы. Не удаляйте их и не меняйте записи прямо в файле во время работы сайта.

Имя базы может отличаться на другом компьютере. Команда `node scripts/data-status.mjs`, запущенная из папки проекта, показывает точный путь и число записей в каждой таблице. Она ничего не изменяет и не выводит пароли или банковские токены. Для этой команды используется Node.js 24, уже установленный на текущем компьютере.

## Какие таблицы за что отвечают

| Таблица | Что хранится | Где смотреть на сайте |
|---|---|---|
| `users` | Имя, email, телефон, город, роль, настройки профиля, признак подтверждения email; пароль хранится как хеш | Кабинет → «Налаштування»; админ-панель → клиенты |
| `sessions` | Защищённые сессии входа и срок их действия | Пользователь входит и выходит через интерфейс |
| `tokens` | Одноразовые токены подтверждения email и восстановления пароля в виде хешей | Страницы подтверждения и восстановления |
| `leads` | Заявки регистрации, контактов, интереса к клубу, тренеру и абонементу | Админ-панель → «CRM / заявки» |
| `lead_notes` | Заметки команды к заявкам | CRM |
| `content` | Карточки клубов, тренеров, тарифы, упражнения, тренировки, программы, рецепты и материалы | Админ-панель → «Контент» |
| `orders` | Заказ, клиент, клуб, тариф, зафиксированная сумма и срок, статус, согласие на сохранение карты | Кабинет → «Замовлення»; панель продаж |
| `payments` | Подтверждения провайдера, номер операции, сумма, статус и минимальные технические сведения | Панель продаж; история заказов |
| `memberships` | Абонемент, владелец, клуб, даты начала и окончания, состояние и код QR-карты | Кабинет → «Абонементи»; панель команды |
| `payment_methods` | Зашифрованный токен LiqPay, платёжная система, безопасный суффикс карты, признак основной карты | Кабинет → «Мої картки» |
| `payment_attempts` | Попытка оплаты сохранённой картой; защита от повторного списания одним заказом | Обрабатывается сервером автоматически |
| `class_sessions` | Занятия, время, клуб, тренер и вместимость | Расписание; панель команды |
| `bookings` | Записи клиентов и отмены | Кабинет → «Мої записи» |
| `workouts` | Личные планы, упражнения и параметры подходов | Конструктор; кабинет → «Тренування» |
| `workout_logs` | Результаты завершённых тренировок | История и статистика кабинета |
| `progress` | Измерения и история прогресса | Кабинет → «Прогрес» |
| `nutrition` | Планы питания и записи блюд | «Харчування» |
| `favorites` | Избранные карточки клиента | Кабинет → «Обране» |
| `notifications` | Уведомления внутри сайта | Кабинет |
| `outbox` | Очередь писем и сообщений, попытки доставки и результаты | Служебные разделы панели администратора |
| `tickets`, `ticket_replies` | Обращения поддержки и переписка | «Підтримка»; панель команды |
| `audit` | Журнал существенных действий | Журнал панели команды |
| `rate_limits`, `telegram_updates` | Защита от частых запросов и повторных событий Telegram | Служебные записи |

Номер карты, CVV и срок действия карты сайт не сохраняет. Ввод реквизитов выполняется в защищённом интерфейсе LiqPay. После успешной оплаты с согласия клиента провайдер выдаёт токен для следующей покупки. SYNKRA хранит этот токен зашифрованным; публичный API возвращает только безопасное описание карты. Раздел «Мої картки» позволяет выбрать основную карту и убрать её связь с аккаунтом SYNKRA.

## Где находятся остальные файлы

| Путь | Назначение |
|---|---|
| `db/schema.ts` | Описание структуры таблиц |
| `drizzle/*.sql` | Версионированные изменения структуры базы |
| `lib/server/` | Код регистрации, платежей, CRM, доступа и автоматизации |
| `lib/catalog.ts` | Исходное наполнение каталога для первой инициализации; правки действующего каталога сохраняются в базе |
| `lib/data/image-assets.json` | Связь карточек с фотографиями, источники, авторы, лицензии и контрольные суммы |
| `public/images/catalog/` | Файлы фотографий WebP |
| `.dev.vars` | Локальные ключи сервисов, email администратора и ключ шифрования платёжных токенов; файл не входит в исходный архив |
| `.sites-runtime/startup.log` | Журнал запуска и ошибок |
| `dist/` | Собранный сайт; этот каталог можно восстановить сборкой |

Удаление `dist` не является удалением клиентов. Удаление `.wrangler/state` затрагивает локальную базу и может уничтожить данные. Файл `.dev.vars` содержит секреты: его нельзя публиковать, прикладывать к открытым репозиториям или присылать посторонним. Потеря ключа шифрования делает ранее сохранённые платёжные токены непригодными для использования.

## Как просматривать, изменять и удалять

1. Получите роль администратора по инструкции «Управление-данными-и-автоматизация.md» и откройте `/admin`. Обычные клиенты доступа к чужим данным не имеют.
2. В «Контент» создавайте и редактируйте карточки. Сохранённая карточка появляется в соответствующем каталоге автоматически. Удаление карточки убирает её из публичного каталога; существующие финансовые записи сохраняют свои связи и историю.
3. В CRM просматривайте заявки, меняйте этап работы и оставляйте заметки. Клиенты, заказы, абонементы и обращения находятся в своих вкладках. Менеджеры видят только назначенные им клубы.
4. Используйте «Експорт CSV» для рабочих выгрузок. Клиент может выгрузить собственные данные в настройках кабинета. Выгрузка не включает пароли, секреты сессий или зашифрованные токены оплаты.
5. Клиент редактирует профиль, планы и питание через кабинет; отменяет запись в «Мої записи»; убирает сохранённую карту в «Мої картки».
6. Закрытие аккаунта выполняется через его настройки с подтверждением пароля. Личные данные удаляются или обезличиваются, финансовая история остаётся обезличенной. В текущей панели нет отдельной кнопки удаления любого клиента администратором.

Для резервной копии остановите сайт и сохраните всю папку `.wrangler/state` вместе с защищённой копией `.dev.vars`. Это полнее, чем CSV. Не переносите один открытый файл SQLite без остальных файлов базы.

## Что будет после размещения в интернете

На хостинге данные будут в облачной Cloudflare D1, а ключи — в защищённых настройках окружения. Они не будут автоматически синхронизироваться с локальной базой этого компьютера. При запуске выбирается, переносить ли локальные данные или начать с новой базы. Проектный архив содержит код и фотографии, но не клиентов, заказы, локальную базу или секреты.

Клубы не появляются как реальные партнёры автоматически из интернет-поиска. После договорённости администратор добавляет действительные сведения клуба, тарифы, расписание и подтверждает подключение. Затем каталог и платёжные сценарии используют эти записи автоматически. Для настоящего приёма денег нужны одобренный аккаунт LiqPay, включённые нужные методы API, HTTPS-домен, ключи, webhook и проверка платежа у провайдера. Для отправки писем требуется отдельный настроенный отправитель; необязательное подтверждение email не включает доставку автоматически.
